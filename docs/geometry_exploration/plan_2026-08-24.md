# Geometry exploration: plan going forward (written 2026-08-24)

## Where the last batch landed

See `baseline_2026-08-24/README.md` for the frozen numbers. Short version:
none of the three new cavity shapes beat the dual-mode reference we already
had. Dual-mode is the only design meeting the -16 dB return-loss spec.
Every design -- all four, independently -- landed at 2.2-2.5x the target
bandwidth. That is the finding worth acting on, not "geometry X is bad":
something about external coupling is over-coupled across the board, and it
was never probed directly because the Bayesian search always tunes `w_iris`,
`w_ext`, `a` etc. jointly, so nothing separates "the aperture is too wide"
from "the cavity is the wrong size" in the result.

## What changes tonight, and why

### 1. A cheap accept/reject screen before every coarse eval

Rationale (user request): most GP/random points in a search are far from
useful and it is wasteful to run a full ~185-230s coarse sweep on a design
that is obviously detuned or mismatched. Added `screen_at_f0()` in
`optimize.py`:

- an ULTRA-coarse mesh (`SCREEN_MESH_PRESETS`, coarser than the search mesh),
  because the measured cost structure this session (COARSE_TOL's benchmark)
  showed meshing/assembly, not per-frequency solves, dominates an eval's
  time. Screening on the SAME mesh as the search would roughly double the
  time for every design that passes, since meshing gets paid twice.
- a short 5-point sweep across the fit window around f0, not a single
  frequency exactly at f0. **This was caught in testing, not assumed**: a
  literal single point at f0 wrongly rejected the landed dual-mode design
  itself (S11 -16dB, real peak IL -1.41dB) because its two-pole response has
  a genuine dip near f0 between the TE102/TE201 poles, and f0 landed almost
  exactly in it. A mid-search design is also routinely 20-50MHz off-centre,
  which the single-point check conflated with "bad design." The fix screens
  the BEST point across the window: "is there a usable resonance anywhere
  near where we want one."
- reject if best-in-window S11 > -10dB OR best-in-window S21 worse than a
  calibrated dielectric-loss floor. **The originally specified threshold
  (dielectric floor + 10% headroom) was also wrong, caught the same way**:
  this session's four confirmed designs measure 2.65x-3.84x the pure
  dielectric-loss number, because SIW cavities carry via/leakage/conductor
  loss the Hong & Lancaster dielectric-only formula never modelled. +10%
  headroom would have rejected every design ever built here, including the
  best one. Calibrated instead to 3.5x, which sits just above the two
  working designs (2.65x, 2.99x) and below the two failed ones (3.84x,
  10.70x) -- see `dielectric_il_db()` / `IL_HEADROOM` in `optimize.py`.

This is now wired into `evaluate()` as the default for every coarse eval
(`screen=True`); the fine confirm is never screened.

### 2. Tonight: push the dual-mode design toward the actual 5% FBW target

The re-tune that finished this afternoon got 20 evals and landed at 320 MHz
BW (2.2x target) -- it was never given the budget to push further, and there
is real room left: `w_ext`/`w_iris` were not pinned against their boxes.
Launching a longer run (larger budget, screen enabled) purely on `dualmode`,
targeting a NARROWER, more selective response. No objective change needed --
`score()`'s bandwidth term is already two-sided and penalizes too-wide
equally; more budget plus the screen (which lets more evals land on live
candidates instead of the search wasting them on dead ones) is the lever.

Saved as `docs/geometry_exploration/baseline_2026-08-24/dualmode_best.json`
before this run starts, so tonight's result can be compared against where it
started.

### 3. Tomorrow: systematic iris/aperture sweeps per geometry AND structural variants

The joint Bayesian search never isolated the coupling knobs from cavity
size. Plan: for each of corner_cut / circular_cross / rhombic, run a 1D or
2D grid sweep of JUST the coupling parameters (`w_iris`, `w_ext`, and
`y_wall` where it applies) at a FIXED, near-resonant `a` (from this
session's screening), using the fast screen to throw away non-starters
before spending a real coarse eval on each grid point. This directly
targets the "was every geometry's bandwidth over-coupled for the same
reason" question the baseline could not answer, because it separates
coupling from cavity size instead of searching them jointly.

Built: `siwfilter/sweep_coupling.py`.

**Widened scope (user request, 2026-08-24 evening)**: the screen isn't only
for ranking parameter values within one fixed shape -- it's cheap enough to
also screen STRUCTURAL variants of each geometry, not just parameter values
within the current one:
  - corner_cut: deeper/more aggressive diagonal truncation than the current
    `w_iris` range explored (the cut saturates at `max(p_via, w_iris)`, so a
    genuinely different corner geometry -- e.g. a stepped or double cut --
    is a different structure, not a parameter value).
  - circular_cross: more vias in the fence (denser ring, or a second
    concentric ring) rather than only tuning the centre cross's arm lengths.
  - rhombic: similar structural variants once the above two are screened.

Goal: use the fast screen to survey MANY structural variants cheaply, then
carry the best ~4 alternatives-to-dual-mode forward into real coarse+dense
optimization, instead of only re-tuning the 3 shapes already tried with the
same via-placement logic.
